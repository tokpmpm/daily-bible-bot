## 任務

請建立或呼叫兩個獨立工作 Session / Agent：

- Session B：Developer
- Session C：Reviewer / QA

不要由你自己假裝扮演 B、C。
必須使用 Codex 實際提供的 thread / agent / session / send-message / handoff / heartbeat / wakeup 等原生能力。

如果目前環境沒有其中某項能力，請明確告訴我缺少哪個工具，不要用檔案模擬。

---

## 測試流程

### Step 1 — A → B

請 Session A 主動傳訊息給 Session B：

「請檢查目前 repository，找一個安全、不影響主要功能的小改善，完成後告訴我你修改了什麼，但先不要通知使用者。」

B 必須自己查看 repo 並完成一個很小的修改。

---

### Step 2 — A 等待 B

Session A 不要自己去完成 B 的工作。

等待 B。

如果 Codex 支援 heartbeat / wakeup：

請設定適當的 heartbeat，讓 A 可以稍後醒來確認 B 是否完成。

如果 B 尚未完成：

A 主動發訊息詢問 B：

「目前進度如何？完成後請直接通知我。」

我要測試 B 的 session 裡是否真的會出現來自 A 的訊息。

---

### Step 3 — B → A

B 完成後：

B 必須主動通知 A：

- 修改內容
- 修改檔案
- 是否有測試
- 是否有任何風險

不要靠我人工複製訊息。

---

### Step 4 — A → C

A 收到 B 的完成通知後，把 B 的結果 handoff 給 Session C。

請 C：

1. 查看 B 真正修改的 code
2. Review 修改
3. 執行適合的測試
4. 判斷 PASS 或 FAIL

---

### Step 5 — C → B

如果 C 發現問題：

不要通知我處理。

C 直接把具體問題傳給 B，要求 B 修正。

B 修正後再主動通知 C。

C 再次驗證。

B ↔ C 可以自行往返，直到 PASS。

---

### Step 6 — C → A

C 驗證 PASS 後，主動通知 A：

「QA PASS」

並附上簡短驗證結果。

---

### Step 7 — A 最終回報

只有整個流程完成後，A 才回覆我。

最後請列出實際發生的協作紀錄：

A → B
B → A
A → C
C → B（若有）
B → C（若有）
C → A

並告訴我：

1. 哪些是實際 Codex session-to-session message
2. 是否使用 heartbeat / wakeup
3. 是否使用 handoff
4. 是否建立獨立 thread / session / agent
5. B、C 的 thread/session 名稱或 ID（如果系統允許顯示）
6. 哪些功能目前環境不支援

## 非常重要

不要用以下方式假裝完成測試：

- 建立 handoff.md
- 建立 message.txt
- 用 STATE.md 傳話
- 用 Git commit message 當作 Agent 通訊
- 由 Session A 自己扮演 B、C

「Codex Agent A 是否真的可以主動聯絡另一個 Codex Session B，等待它、喚醒自己、收到 B 的回覆，再把工作交給 C。」

如果原生能力不可用，測試失敗也沒關係。
